# Query Managers

Kribton features it's own Query manager built on top of SQLalchemy to ease the database data querying.

- `AsyncQueryManager` (used automatically by `AsyncDatabase`) currently provides:
    - `await Model.objects.all()` — `SELECT` over all rows, returned as a list of plain dicts.
    - `await Model.objects.filter(**kwargs)` — equality-filtered `SELECT`, AND-combining every keyword argument. Returns a list (empty if nothing matches).
    - `await Model.objects.get(**kwargs)` — same filtering as `.filter()`, but returns a single dict or `None`.
    - `await Model.objects.create(**kwargs)` — inserts a new row and returns the full serialized record, including any autogenerated fields (e.g. primary key, defaults).
    - `await Model.objects.update(pk, **kwargs)` — updates the row matching the primary key with the given fields, returning the updated record or `None` if no row exists with that pk.
    - `await Model.objects.delete(pk)` — deletes the row matching the primary key. Returns `True` if a row was deleted, `False` if no row existed.
    - `serialize(obj)` — converts a SQLAlchemy model instance into a `{column_name: value}` dict using its table's columns.

## Create

```python
task = await Task.objects.create(title="Write docs", done=False)
# {"id": 1, "title": "Write docs", "done": False}
```

## Read

```python
all_tasks = await Task.objects.all()
pending = await Task.objects.filter(done=False)
one_task = await Task.objects.get(id=1)  # dict or None
```

## Update

```python
updated = await Task.objects.update(1, done=True)
if updated is None:
    # no task with id=1
    ...
```

## Delete

```python
deleted = await Task.objects.delete(1)
# True if a row was removed, False if id=1 didn't exist
```

## Notes and limitations

- **Single-column primary keys only.** `update()` and `delete()` reflect the model's primary key automatically, but raise `NotImplementedError` for composite primary keys.
- **No partial-update validation.** `update(pk, **kwargs)` will happily set any valid column to any value — there's no schema/type validation on the values themselves (e.g. setting a string column to an int won't be caught here; SQLAlchemy/the database may or may not complain depending on the backend).
- **Unknown fields fail fast.** Passing a keyword that isn't a real column to `create`, `update`, `filter`, or `get` raises `AttributeError` immediately rather than silently doing nothing.
- **No bulk operations.** Each `create`/`update`/`delete` call affects exactly one row. There's no `bulk_create()` or `update_many()`/`delete_many()` yet.
